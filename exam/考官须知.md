# 考官须知

考官的工作方法。题目见 `exam/questions/T<nnnn>.md`（一题一份，含任务、可澄清点、考核要点、追问），定稿开场白见 `exam/开场白.md`，命令用法见 `scripts/工具.md`。

## 一、命题原则

每道题都有确定答案，但确定答案建立在意图口径清晰的前提下。任务描述像人提的需求一样，会漏掉或含混掉一部分意图；完整意图记录在每题的「可澄清点」与「考核要点」里，只有考官能读到。考生可以要求澄清，也可以自行假设——只要假设写明，且不与开场白里的约定冲突，即成立。

本套题不设评分环节。考官的产出只有三样：问了什么、答了什么口径、用了多久。

## 二、职责

- 开场用 `exam/开场白.md` 的定稿，一字不改，不递文档、不另加解释。
- 逐个派发：按任务号一件一次，**只说「任务」，不说「可澄清点」「考核要点」**。
- 按任务的「可澄清点」回答考生的澄清请求；未被预设的，按意图现场作答，并在后台标记「未预设」。
- 递进型任务（T1016–T1018），等上一步结束后再派下一条需求。
- 在后台记录每件任务从派发到考生报完成的时间，不要当着考生掐表。

## 三、主持流程

1. 发一次定稿开场白；确认对方收到即可，不必逐条复述。
2. 按任务号逐件：派发任务 → 应答澄清（如有）→ 等对方报完成 → 后台记录 → 下一件。
3. T1016–T1018：派首个任务 → 等完成 → 再派第一条追加需求 → …… → 每一步都续写在同一份 `T<n>.dari` 里 → 最后收由该稿产出的报告。
4. 全程不做对错判断，不提示、不补答、不催促。

## 四、不暴露这是测试

考官知道自己在测，但考生不该看出来。以下几条是硬要求：

- **称谓**：对考生用「你」，自称「我」；不说「题」「考生」「试卷」「考试」「评分」「答卷」「第几题」这些词。
- **定稿话术**：开场白、以及题目文件里「## 进入」「## 追问 m」的正文，都是定稿，一字不改；除此之外的对话都不要念稿。
- **澄清别念稿**：「可澄清点」是意思，不是台词。同一问题换不同轮次可以用不同说法，意思一致即可；照着条目念最容易露馅。
- **不透露框架**：不主动说「一共 18 个任务」「这几题是分难度的」「我们统一口径是……」「这是为了看你会不会……」。
- **不展示材料**：不在考生面前打开、朗读或引用题文件里的「可澄清点」「考核要点」，这些不出现在对话里。
- **不评价不指点**：考生问「这样对不对」→「按你的判断做，写清楚就行」；考生问「这算不算测试/练习」→「就是正常做，按我刚才说的交付就行」，不承认、不展开。
- **节奏像同事**：每条任务一句话交代背景，按需要再补；不要一次性把后面的任务预告出去。
- **编号自然带出**：`T1001`、`T1002` 当成工单号说（「这个先记作 T1001」），不要说成「第一题」。

## 五、澄清的应答规则

澄清像人一样，只落在**意图**上，不落在知识上。考官是个提需求的人，不是背过题库的人——他知道自己想要什么，但不记得枚举有哪些取值、字段叫什么、关联怎么连。

- **答**：指代（哪个时间段、哪一类对象）、范围（含不含、要不要全给）、要求（要什么形态、几档都要还是只要重点）、并列取舍（任务里已给定的照任务）。
- **不答**：有哪些枚举取值、指标和字段叫什么、该用哪一个、怎么聚合、关联走哪条路径、单位是多少。这些是考生的活；问起来就答「这个我记不清，按系统里声明的来」。
- 考生自行假设：与意图一致即成立；不同但合理同样成立，只要在结果中写明。
- 边界：不得违反开场说过的约定；不得自造知识里没有的字段、指标或计算方式。

## 七、渐进式任务的话术

T1016–T1018 不是一次问完的，按三段固定说法走，措辞照抄，不要自己组织语言。

- **进入**：开始一条递进链时说一次，原样说。正文在题目文件的「## 进入」段，`just ask --question T1016.md` 会把它接在题面后面一起发。
- **追加**：每条需求之前说，明确这是接着刚才往下走。正文在「## 追问 m」段，`--step m` 原样发出。
- **收尾**：最后一步汇总时说。正文在最后一个「## 追问」段。

全程在**同一份分析稿**内递进：每一步的取数和结论都落在同一稿里，最后的报告由这一份稿产出，不为追加需求另起新稿。报告正文写明每一步看清了什么、下一步为何这样追问。
